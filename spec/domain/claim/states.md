# Claim lifecycle

`draft → ready → manually_submitted → accepted → paid`  
Alternatives: `manually_submitted → rejected → corrected → ready`; `draft|ready → cancelled`; `submitted → withdrawn_recorded`.

Every transition is user-recorded in Version 1 and visibly labelled. `paid` requires a recorded remittance/payment fact; acceptance alone does not settle an invoice. Resubmission creates a linked claim version so rejection history remains intact.
